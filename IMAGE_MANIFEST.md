### How each file was checked

1. **On disk.** This script re-opens every file. Raster files are decoded with sharp and their width and height are compared with the inventory. SVG files are checked for a valid `<svg … viewBox>` document.
2. **Referenced correctly.** `npm run check:images` runs before every `npm run build`. It collects every image path in `src/`, `index.html`, CSS and the web manifest, plus every image record in the data files. Each one must exist and match the dimensions the data declares. Remote image URLs fail the build. Negative tests confirmed this: removing one product image, or adding one remote URL, makes the build exit with an error.
3. **In the browser.** `node scripts/verify-site.mjs` serves the production build with `vite preview` and checks it in Chromium:
   - It loads 43 routes at desktop, tablet, mobile and 2× desktop: 172 page views and 1412 rendered images.
   - It fails on any broken image, fallback, failed request or console error.
   - It clicks through product galleries.
   - It fetches and decodes every generated file directly.
   - Result: 0 failures, 13 of 13 interaction tests passing.

"Shown on a page" in the tables below means the browser picked that exact file while rendering a page in the crawl. Browsers load one `srcset` candidate per image, so a full-size or `-sm` variant may not be picked at a given viewport. Gallery close-ups and box shots for products other than the tested one only load after a thumbnail click. Those files are still covered by the direct decode check.

## Regenerating or replacing images

- `npm run images` re-renders all files from code. The output is deterministic.
- To swap in a real photograph, keep the same filename, or update the `src`, `width` and `height` in `src/data/*.ts`. Then provide the `-sm.webp` variant and run `npm run build`. The image check will fail if the dimensions do not match.
- Only use photographs you have the rights to: your own, commissioned, or licensed stock. Get signed consent from any staff member or patient shown.
